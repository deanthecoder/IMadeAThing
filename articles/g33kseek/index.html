Why I Built a Spotlight-Style Launcher for Windows

2026-09-18

I use both Windows and macOS, and one feature I always miss when moving back to Windows is Spotlight.

On the Mac it has become muscle memory: press a shortcut, type a few characters, open the thing I want and carry on with what I was doing. Windows has plenty of ways to find applications and files, but none of them felt quite as immediate or behaved exactly the way I wanted.

So I built my own.

G33kSeek is a lightweight keyboard launcher written in C# using Avalonia. Its main purpose is simple: press a global shortcut, type a query and get out of the way again.

It also runs on macOS because I spend a lot of time developing there and Avalonia makes most of the application naturally cross-platform. That is useful, but it is not the reason G33kSeek exists. I primarily wanted a Spotlight-like launcher for Windows.

One shortcut, then type

G33kSeek appears using Ctrl+Alt+Space on Windows or Ctrl+Space on macOS. From there I can search for an installed application, file or folder without choosing a search mode first.

The results are deliberately keyboard-friendly. The arrow keys move between them, Enter performs the main action and Escape dismisses the window. Files and applications also provide secondary actions for things such as revealing an item in Explorer or Finder and copying its path.

Direct paths and URLs work too. If I already know where something is, I can paste or type the location rather than waiting for it to appear in an index.

A tiny query language

Normal text searches applications, files and folders, but a few prefixes make the same input box useful for other small jobs:

rider
=sin(pi / 2)
10mb in bytes
255 in binary
:wave
?"avalonia docs"
>downloads

An equals sign performs a calculation. A colon searches for emoji and understands a few familiar emoticons. A question mark displays help or performs a quoted web search. A greater-than sign runs one of G33kSeek's built-in commands.

Commands can open useful locations such as Downloads, Desktop, AppData and the temporary directory. Others generate a GUID, refresh the search index, open the log or perform system actions.

These are intentionally small conveniences. None is significant enough to justify opening a separate tool, but together they save a surprising amount of interruption.

Search without stopping to search

The difficult part of a launcher is not displaying a list. It is producing useful results on every keystroke without making the interface hesitate.

G33kSeek discovers applications differently on Windows and macOS, then combines those results with a cached file and folder index. The index is built in the background from common user locations rather than walking the file system for every query.

Queries are routed through focused providers for normal searches, calculations, emoji, commands and help. This keeps each mode small while still presenting everything through one input box.

I have spent rather more time than expected making the file index behave itself. A large index can consume plenty of memory if every entry stores repeated path data and heavyweight file-system objects. G33kSeek now shares repeated parent paths, stores compact search data and only creates FileInfo or DirectoryInfo objects when an action actually needs one.

Searches are cancellable because an answer to the previous keystroke is already obsolete. Potentially slow availability checks happen only for shortlisted results, and network paths are treated carefully so an unavailable machine cannot freeze the launcher.

Most of this work is invisible—which is exactly the point. A launcher that pauses while trying to be helpful quickly stops being useful.

The launcher I wanted

G33kSeek is not intended to be a replacement shell or a huge automation platform. It is the small window I wanted to be able to summon anywhere on Windows: quick to open, quick to search and easy to extend when I notice another repetitive job.
